# Upgrades (Perks and Items) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a level-up screen offering 3 cards (15 perks and 7 rare one-shot items), an items panel with C/V controls, and every perk and item rule from the spec, without changing how a run with no perks plays.

**Architecture:**
- Pure rules go in two places:
  - **New `js/upgrades.js`:** perk and item data, offers, the inventory, the rule options, the timing helpers and scoring.
  - **`js/logic.js`:** word finding, clear helpers and dealer changes.
  - Both are Node-testable through a new check runner, `tools/check-upgrades.cjs`, plus one file per area in `tools/checks/`.
- Pixel art lives in a new `js/icons.js`.
- **`js/game.js`** gets the `levelup` state, the HUD, item firing and the perk hooks.
- **Execution:** Phase 1 builds the shared foundation in order. Phase 2 runs three tracks in parallel, each in its own worktree; every track owns named functions that Phase 1 left as stubs. Phase 3 merges and verifies.

**Tech Stack:** plain browser JS (globals through `<script>` tags, which also export `module.exports` for Node), canvas 2D, Node 24 for checks, and headless Chrome over CDP for screenshots.

**Spec:** `docs/superpowers/specs/2026-10-16-upgrades-design.md` (read it alongside this plan). The background is in `docs/upgrades-notes.md`.

## Global Constraints

- The game must run from `file://` with zero dependencies:
  - no `fetch()`, no ES modules in the browser;
  - every new file is a plain `<script>` setting a global, and also sets `module.exports` when `module` exists.
- Script order in `index.html`: `words.js`, `font.js`, `icons.js`, `logic.js`, `upgrades.js`, `game.js`.
- Drawing:
  - pixel-perfect on the 320×272 canvas;
  - every draw coordinate is an integer;
  - `imageSmoothingEnabled = false`.
- Palette: only `BLACK`, `WHITE` and `RED`, plus `GREY`, `DIM` and `DIMRED`. Use dithering, never new colours.
- `js/words.js` is generated by `tools/build-words.mjs`. Never edit it by hand.
- Card text: at most 14 characters per line, using only glyphs that exist in `js/font.js`. There is no `%` or `×`; write `X2`.
- **A run with no perks and no items behaves exactly as it does today:**
  - `node tools/check-logic.cjs` passes unchanged;
  - `node tools/simulate.cjs` reproduces the baseline table in `CLAUDE.md` exactly (for example hooks 1127/1281 and targets 347/351 for `gen+hooks+tgts`).
- Keys:
  - SPACE is hard drop (and takes a card on the level-up screen).
  - ↑, X and W rotate; Z rotates the other way.
  - C fires the selected item; V moves the item selection.
  - ENTER also takes a card.
  - P, H and M are unchanged.
- `localStorage` only uses the existing `wordwell.*` keys, wrapped in try/catch. Nothing about a run persists.
- End every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **SPACE mashed as the level-up screen opens.** Hard-drop habits mean a take often arrives within milliseconds. The expectation is that no card is taken until about 500 ms have passed. *Pinned in Task 6, Step 4.*
2. **One clear crosses two levels** (with `?fast`, or a big chain). The expectation is two screens back to back, then one resume. *Pinned in Task 6, Step 4.*
3. **C or V pressed outside a falling piece:** title, paused, mid-clear, settling, level-up or game over. The expectation is that nothing happens and the item is kept. *Pinned in Task 7, Step 4.*
4. **A new game after game over.** Perks, items, pending level-ups, the Joker count and FREEZE time must all start fresh. *Pinned in Task 6, Step 4 and Task 14, Step 4.*
5. **Hints under changed rules** (MIRROR, SHORT FUSE, PURIST, wild tiles). The red hint must show exactly what would clear. *Pinned in Task 8, Step 4 and Task 9, Step 6.*

**Interfaces:**
- Consumes: `L.scoreWord`, `L.TARGET_BONUS`, `L.makeRng`.
- Produces, on `window.WordWellUpgrades` / `module.exports`, referred to as `U` from here on:
  - `FAMILIES = ['PACE', 'WORDS', 'BLAST', 'GEAR', 'SCORE']`
  - `PERKS: { [id]: { name, family, max, excludes?, text(minLen, run) → string[] } }`. The ids, in spec order, are `feather sticky daredevil mirror shortfuse purist crossfire sinkhole quake packrat bigbang joker stretch aftershock scrabbler`. The names are the spec's (`'SHORT FUSE'`, `'PACK RAT'`, `'BIG BANG'` with spaces). `max` is 3 for feather and 1 for every other perk. `shortfuse` has `excludes: 'purist'` and `purist` has `excludes: 'shortfuse'`.
  - `ITEMS: { [id]: { name, text(minLen, run) → string[] } }`. The ids are `bomb wild reroll drill freeze ibeam beacon`, and the names are `BOMB WILD REROLL DRILL FREEZE I-BEAM BEACON`.
  - Constants: `ITEM_CHANCE = 1/8`, `PACK_RAT_CHANCE = 1/4`, `JOKER_EVERY = 10`, `FREEZE_MS = 5000`.
  - `newRun() → { perks: {}, items: [], sel: 0, joker: 0 }`
  - `count(run, id) → number` and `has(run, id) → boolean`
  - `perkPool(run) → id[]`
  - `offerCards(run, rng) → [{ kind: 'perk' | 'item', id }]` (always 3)
  - `takeCard(run, card)` and `addItem(run, id)`
  - `selectedItem(run) → id | null`
  - `selectNext(run)`
  - `useItem(run) → id | null`
  - `rules(run, minLen) → { minLen, shortLen, mirror, rareBoost }`
  - `gravityMs(run, level) → number` and `lockDelayMs(run) → number`
  - `bombRadius(run) → 1 | 2`
  - `chainFactor(run, chain) → number`
  - `wordPoints(found, chain, run, { hit, minLen }) → integer`
  - `jokerDue(run) → boolean`. Call it once per dealt piece; it counts only while JOKER is owned.
  - `quakeNow(run, chain) → boolean`: `has(run, 'quake') && chain === 3`.
- Produces in logic: `scoreWord(word, mult = 1, opts = {})` with `opts = { rareMult = 1, wildChs = [] }`, and `SCRABBLE_RARE = new Set(['j', 'k', 'qu', 'x', 'z'])`.

- [ ] **Step 4: Implement `js/upgrades.js` and the `scoreWord` options**

- **Card text** is copied from the spec tables (§3, §4).
  - SHORT FUSE's first line is `` `${minLen - 1}-LETTER` ``, and PURIST's is `` `${minLen}-LETTER` ``.
  - BOMB's text reads `3X3`, or `5X5` when `has(run, 'bigbang')`.
  - Item text starts with `C:`.
- **`perkPool(run)`:** a perk is in the pool if `count < max` and its `excludes` perk isn't owned.
- **`offerCards(run, rng)`:**
  - Each slot rolls `rng() < chance` for an item, where chance is `PACK_RAT_CHANCE` with packrat and `ITEM_CHANCE` otherwise. Stop rolling after the first item. An item's type is uniform over the 7.
  - The other slots draw perks without replacement, weighted 2 if the perk's family has any owned perk and 1 otherwise.
  - When the pool is empty, a slot takes an item type not already on the screen.
- **`useItem(run)`** decrements the selected stack. An empty stack is spliced out, and `sel` becomes 0 if it is now past the end.
- **`gravityMs(run, level)`:** `Math.max(70, 900 * Math.pow(0.86, lvl - 1)) * Math.pow(4 / 3, count(run, 'feather'))`, where `lvl = level + (daredevil ? 2 : 0)`.
- **`wordPoints(found, chain, run, { hit, minLen })`:**
  - 0 if `found.short`.
  - Otherwise: `L.scoreWord(found.word, chainFactor(run, chain), { rareMult: scrabbler ? 3 : 1, wildChs: found.wildChs || [] })`
  - × `L.TARGET_BONUS` if hit
  - × 1.5 for daredevil
  - × 2 for purist when `found.word.length > minLen`
  - × 2 for stretch when `found.word.length >= 6`
  - then `Math.round`.
- **`scoreWord` in logic:** each letter's points (walking `qu` as one tile, as today) are multiplied by `rareMult` when the letter is in `SCRABBLE_RARE`. Then subtract each letter in `wildChs` the same way (times `rareMult` if rare). Floor the sum at 0. The call `scoreWord(word, chain)` must return exactly what it returns today.
- **Module loading:** at the top, `const L = root.WordWellLogic || require('./logic.js');`.

### Task 3: Clear helpers and broken targets

**Files:**
- Modify: `js/logic.js` (new helpers, `TargetTracker.broken`, exports)
- Test: `tools/checks/clears.cjs`

**Interfaces:**
- Produces, with every cell given as `{ x, y }` and every key as the string `"x,y"`:
  - `rowCells(grid, y) → cell[]`: the occupied cells in that row.
  - `columnCells(grid, x) → cell[]`
  - `crossCells(grid, found) → cell[]`: the occupied cells on the line perpendicular to `found`, through its middle tile. For even lengths that's the left or upper of the two middle tiles, chosen after sorting the cells by position.
  - `blastAround(grid, keys, found, radius) → Set<key>`. It returns a new set containing:
